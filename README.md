# חניה ליד הקיבוץ — בלומפילד

אותו ממשק של הגרסה המקורית, עם משיכת נתונים אמיתיים ממקורות רשמיים. ״כנראה״ מופיע לצד הכותרת, ו״באזור״ הוסר מהשורה הדקה.

## הנתונים

העדכון רץ ב־GitHub Actions מדי חצי שעה (בדקות 13 ו־43), גם כשהאתר סגור. אין צורך במפתח API, הרשמה לשירות scraping, או מנוי בתשלום. GitHub עשוי לעכב או לדלג על ריצות מתוזמנות; לכן האפליקציה בודקת בעצמה את גיל המידע.

| מקור | מה נמשך |
| --- | --- |
| היכלי הספורט — פיד iCalendar לספורט | אירועים עם מיקום מפורש בבלומפילד |
| היכלי הספורט — פיד iCalendar לתרבות | הופעות ואירועי תרבות בבלומפילד |
| ההתאחדות לכדורגל — מכבי ת״א | משחקים, מועדים ואצטדיונים |
| ההתאחדות לכדורגל — הפועל ת״א | משחקים, מועדים ואצטדיונים |
| האתר הרשמי של מכבי ת״א | הצלבת שעות, מיקום ומועדים לא סופיים |
| API רשות הספורט העירונית | לוח אירועים מפורסם עד שנה קדימה, עם בדיקת עימוד |

אלו שישה פידים מארבעה מפרסמים. פידים של אותו ארגון נספרים כמפרסם אחד. ההתאחדות עלולה להחזיר 403 משרתי GitHub; אין להציג את העותק השמור כאילו נבדק עכשיו. גגרין ודופלקס נבדקו אך חסמו גישה מהסביבה; הם אינם מקורות מחוברים כרגע. אין כיסוי מובטח לכל אירוע בסביבה.

## אמינות וקבלת החלטות

- זו הערכת ״כנראה״ לפי לוחות אירועים שפורסמו, לא מדידה של חניות פנויות.
- לוח שנבדק נשאר בסיס להערכה גם אחרי שעתיים, יממה או כשל בעדכון הבא. אין פסילה לפי גיל בלבד. זמן ההצלחה האחרון נשמר ומוצג; עיכוב בעדכון מצוין בנפרד.
- **ירוק:** לא נמצא אירוע בתאריך המבוקש, בתוך טווח הלוח שנאסף, ויש לוחות מלאים משני מפרסמים עצמאיים לפחות, ובהם מפעיל האצטדיון או העירייה. אפשר להסתמך על הבדיקה המוצלחת האחרונה גם בזמן כשל במשיכה. פענוח חלקי לא מוכיח שאין אירוע.
- **אדום:** קיים אירוע עם שעה ומיקום ידועים וללא סתירה. חלון העומס הוא הערכה — שלוש שעות לפני ועד שעתיים וחצי אחרי תחילת המשחק. חציית חצות נשמרת בתאריך הנכון.
- **לא סופי:** פרטי האירוע חסרים או שהמקורות סותרים זה את זה. תצפיות חדשות מקבלות קדימות על פני עותקים קודמים. לא ממציאים שעות.
- **אין מספיק מידע:** לא התקבל מידע שמיש, אין מספיק לוחות שנבדקו, או שהתאריך מחוץ לטווח שנאסף. עיכוב בעדכון לבדו לא גורם למצב הזה.
- עדכון שנכשל שומר גם את מידת השלמות של המשיכה המוצלחת האחרונה. אין סימון של עותק שמור כבדיקה חדשה. אירועים עם פרטים סופיים ניתנים לייצוא ליומן גם בזמן עיכוב.

## הפעלה ובדיקות

Python 3.11 ומעלה ו־Node 22; אין תלויות להתקנה.

```sh
python scripts/update_games.py
python -m unittest discover -s tests -p 'test_*.py'
node --test tests/data.test.cjs
```

קובצי האתר הם `index.html`, `data.js`, `games.json`. `data/source-cache.json` שומר את התגובה המוצלחת האחרונה מכל מקור, כדי שריצה תקולה תוכל להציג מידע חלקי ביושר.

## האתר הציבורי והתחזוקה

[פתיחת האפליקציה](https://kibbutz-entrance.github.io/bloomfield-parking/)

המאגר והאתר פורסמו לציבור באישור מפורש של המשתמש ב־2 בנובמבר 2026. GitHub Pages מוגדר לפרסום באמצעות Actions. כל שינוי ב־main, ריצה ידנית או הריצה המתוזמנת מרעננים את הנתונים ומפרסמים את האתר. אין משתנה הפעלה נוסף ואין מפתח API.

פריסת הייצור הראשונה אומתה בריצה 41530238351: בדיקות, משיכה, שמירת הנתונים ופריסה הצליחו. ארבעת פידי הליבה התעדכנו בהצלחה; שני פידי ההתאחדות החזירו 403 ומוצגים כמקורות משלימים שאינם זמינים. גם כתובת האתר הציבורית וקובץ הנתונים נבדקו בפועל.

לבדיקת תקלה: לפתוח את הריצה האחרונה ב־Actions, לבדוק את שלב Pull official public sources ואת מצב כל מקור ב־games.json. אין לעדכן ידנית חותמת זמן של מקור שנכשל. כשלי מקור נשמרים ומוצגים גם כשהפריסה עצמה מצליחה.

### Deployment and backup recovery

The workflow validates the generated website, uploads the Pages package and a seven-day
`source-snapshot` artifact, and deploys only if its repository revision is still current.
Repository backup saving runs as a separate job after deployment. It retries temporary
Git failures, detects a push that succeeded despite a lost response, and never overwrites
a competing revision. A failed backup job means the website may already be updated;
check the deploy job before retrying. The artifact contains `games.json` and
`data/source-cache.json` for recovery. A newer main revision owns the next refresh.

Run `python -m unittest discover -s tests -p 'test_*.py'` and
`node --test tests/*.test.cjs` for deterministic validation. The workflow additionally
runs `node scripts/validate_site.cjs dist data/source-cache.json` AFTER fetching live data
and preparing `share.html`. Source outages are valid publishable health states; malformed
packages and unverifiable revisions stop publication. GitHub cron is best effort;
source timestamps disclose freshness separately from the usability of published schedules.

Published schedule evidence has no age-only expiry. Delayed schedules never count as newly checked.
